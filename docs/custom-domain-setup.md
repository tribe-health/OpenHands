# Setting Up OpenHands with a Custom Domain

This guide explains how to configure OpenHands to work correctly with a custom domain instead of localhost.

## How It Works

Our implementation uses a dual-URL approach:
1. **Internal connections**: Always use `http://localhost` for internal API connections to ensure the runtime can connect to itself
2. **VSCode URL**: Use the custom domain from `CUSTOM_DOMAIN_URL` specifically for the VSCode URL

This approach ensures that:
- The runtime can always check if it's alive using localhost
- The VSCode URL exposed to the client uses the custom domain
- No complex URL rewriting is needed in the Nginx configuration

## Environment Variable Configuration

The key to making OpenHands work with a custom domain is setting the `CUSTOM_DOMAIN_URL` environment variable to your domain name. This ensures that the VSCode URL generated by OpenHands uses your domain instead of localhost.

### Setting the Environment Variable

Before starting your OpenHands server, set the environment variable:

```bash
export CUSTOM_DOMAIN_URL=openhands.skytok.net
```

Replace `openhands.skytok.net` with your actual domain name.

For a permanent solution in a production environment, you can add this to your startup script or systemd service file.

### Example systemd Service Configuration

If you're using systemd to manage your OpenHands service, you can add the environment variable to your service file:

```ini
[Unit]
Description=OpenHands Service
After=network.target

[Service]
User=openhands
WorkingDirectory=/path/to/openhands
ExecStart=/path/to/openhands/start_script.sh
Restart=on-failure
Environment=CUSTOM_DOMAIN_URL=openhands.skytok.net

[Install]
WantedBy=multi-user.target
```

## Docker Compose Configuration

If you're using Docker Compose, you can add the environment variable to your `docker-compose.yml` file:

```yaml
services:
  openhands:
    # ... other configuration ...
    environment:
      - CUSTOM_DOMAIN_URL=openhands.skytok.net
      - DOCKER_CONTAINER=true  # Required when running in Docker
```

## Nginx Configuration

With the `CUSTOM_DOMAIN_URL` environment variable set, you can use a simplified Nginx configuration without complex URL rewriting. See the example configuration in `nginx.conf.example`.

The key points in the Nginx configuration are:

1. Standard proxy settings for WebSocket support
2. Setting appropriate headers for HTTPS
3. No need for URL rewriting or JavaScript injection for VSCode URLs

## Troubleshooting

If you're still seeing localhost URLs:

1. Verify that the `CUSTOM_DOMAIN_URL` environment variable is correctly set
2. If running in Docker, make sure the `DOCKER_CONTAINER` environment variable is set to `true`
3. Restart the OpenHands service to ensure it picks up the new environment variables
4. Check that both the local and Docker runtime implementations are using the updated code

## Additional Notes

- The `CUSTOM_DOMAIN_URL` should be set to just the domain name (e.g., `openhands.skytok.net`), not the full URL with protocol
- The code will automatically add the `http://` prefix when constructing URLs
- If you're using HTTPS (recommended), your Nginx configuration will handle the protocol upgrade
